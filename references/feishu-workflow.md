# 飞书衔接与验收

## 读取工具说明

从当前技能目录中定位 `lark-doc` / `lark-whiteboard`，按其入口要求读取相应参考。它们可能在 `~/.agents/skills`，也可能在其他已配置技能目录；不要假设与本技能同级。

- 创建/编辑文档：`lark-doc` → 共享认证规则、XML、写作风格及 create/update workflow。
- 插图：`lark-doc` 的 media-insert 和相关 block 操作说明。
- 新建画板：`lark-doc` 的 whiteboard 说明；更新已有画板：`lark-whiteboard`。
- 本技能不复制一套长期不变的 CLI 参数。执行前查本机说明，失败时先核对版本/权限/语法；不因发现新版而自行更新 CLI。

## 制作与写入

1. 在任务工作目录保存数据、图源码和渲染结果；对外只交付必要文件。模板只复制，不就地修改安装目录里的源文件。
2. 定量图先本地渲染并查看。PNG 用于可靠显示，SVG/脚本保留作编辑来源；图注和来源链接同时保留为原生文档文本。
3. 新建画板时，Mermaid 或自包含 SVG 通过当前飞书技能规定的方式插入。需要子代理的画板路径依其当前规则委派；每个任务有明确图形范围，避免多个代理并发修改同一文档顺序。主代理仍负责最终核查。
4. SVG 用 `viewBox`、显式坐标和 `<text>/<tspan>`；不要把中文转路径冒充可编辑文本。优先简单形状、连线和分组。避免远程资源、脚本及解析器不支持的 filter/mask/clipPath 等特性。
5. 本地预览不等于画板导入后的效果。导入可能重排中文、改变字体或将部分对象降级为图片，需要导出实际画板检查。

## 插入位置与修改边界

- 图片插入快捷命令可能默认追加文末；需要图文相邻时，根据当前支持的 block 插入/移动操作放到正确章节，不能把图片全留在文末就宣称编排完成。
- 写入后重新获取新 block ID。替换、删除、覆盖导致旧 ID 失效时，不复用旧 ID。
- 更新已有画板时先读取；整体替换和增量插入语义不同，按任务意图选用，不无意叠加一张新图。
- 遇到超时或返回不明，先回读核实是否已经写入，再决定重试；复用适用的幂等机制，避免重复图形。
- 用户只要求某节可视化时，不覆盖整篇。修复画板优先局部修订；删除重建不能绕过现有审批要求。

## 验收层次

| 检查 | 可以证明 | 不能证明 |
|---|---|---|
| 本地打开 PNG/SVG | 本地字形、标签、连线、坐标和尺寸可读 | 飞书导入后效果相同 |
| API 写入返回成功 + 内容回读 | 对象已存在、图文位置和资源引用可核对 | 读者页面显示正常 |
| 导出新画板图片并查看 | 飞书画板渲染可见、文字与线条布局可核对 | 整篇页面与移动端体验已验证 |
| 打开实际文档查看相关章节 | 该页面状态下的图文布局、显示宽度、导航可核对 | 其他设备或导出格式也已通过 |

## 画板自动质量检查

每次制作或更新画板后主动执行以下检查，无需等待用户指出问题：

1. 查看导出的实际画板，并在可访问时查看文档中的实际显示：判断图是否过长、空白过多、缩放后文字过小，以及有无遮挡、截断、错位或连接关系不清。
2. 如果纵向图过长影响阅读或页面观感，结合内容尝试横向排列、分行或拆图；横向图过宽时同样检查文字缩放和横向滚动，必要时改回分层或拆图。
3. 对发现的实际问题，在授权范围内调整并重新查看飞书渲染；同时核对文字、数字、来源和连接关系没有因调整改变。达到可读且无已知问题后停止，不为形式反复调整。
4. 若无法打开实际页面或导出画板，完成可用的本地及内容回读检查，并在交付时明确未验证的显示范围，不声称自动检查全部通过。

按已授权范围完成能做的核查，明确不能做的部分，不增加固定轮次或穷尽设备测试。已有合格原图无需反复美化。
